# Guitarbook · 吉他宝典

[简体中文](README.md) · [English](README.en.md) · [日本語](README.ja.md)

Flutter 製のギター練習・即興演奏ツール集です。ドラムマシンでリズムを作り、Looper でフレーズを重ね、リアルタイムエフェクトで音を整えられます。

## ドラムマシン × Looper × エフェクト

- **ドラムマシン**：4/4、3/4、2/4、5/4、6/8、7/8 の 6 種類と、22 種類の練習用プリセット（4/4 ではロック、ファンク、ブルース、ポップ、フォーク、パンク、メタル、ディスコ、レゲエ、ヒップホップ、ジャズスウィング、ラテン。3/4 はワルツとスウィングワルツ、2/4 はファストパンクとマーチ、5/4 はプログレッシブロックと 5 拍スウィング、6/8 は 6/8 スウィングとスロー blues、7/8 は前衛ロックとバルカン）。1 小節の 16 分音符グリッド（x/4 は 1 拍 4 ステップ、x/8 は 1 拍 2 ステップ）でキック、スネア、ハイハット、拍手、コンガの 5 トラックを編集。30–240 BPM、スウィング、トラック別ミュート、音量調整に対応します。
- **Looper**：最初のループは 0.3–30 秒、最大 6 レイヤー。直前のレイヤーの取り消し、任意の 1 レイヤーの削除（削除後に 1 回だけ取り消し可能）、停止・再開、全消去が可能です。スマート録音では周囲のノイズを測定し、演奏開始で録音、約 2 秒の無音で終了して前後をトリミングします。キーボードやキーボード入力を送る USB フットスイッチを割り当てられます。
- **リアルタイムエフェクト**：ファズ、コンプレッサー、リバーブ、オーバードライブ、ディレイ、手動／自動切替ワウ、移調と、アメリカン・クリーン、ブリティッシュ・チャイム、ブリティッシュ・ロック、モダン・ハイゲインの 4 種類のオリジナルアンプ。最大 8 個を直列接続し、ドラッグによる並べ替え、個別調整、バイパスが可能です。Linux / Windows は対応する VST3 エフェクトも読み込め、端末に導入済みの VST3 / VST2 プラグインをスキャンして「外部プラグイン」パネルからワンクリックで読み込めます（VST2 は既定では一覧表示のみで，真正な読み込みには Steinberg VST2 SDK が必要），ゲームパッドのアナログトリガーをワウのエクスプレッションペダルとして使えます。デスクトップブラウザーでも同じ内蔵ペダル・アンプを利用できます（今回の変更・実装済み、ページ全体の自動実測は通過、実機での聴感は未検証。VST3、プラグインスキャン、ウェット Looper には対応しません）。また今回、デスクトップブラウザーではブラウザーの Gamepad API を使ってゲームパッドのアナログトリガーを読み取れるようになりました。
- **同じ画面で即興演奏**：ホームの「即興ワークスペース」カードから開くと、3 つのツールを音量別に操作できます（エフェクトはワークスペース内にあるため、独立したエフェクトの入口はホームから削除されました）。エフェクトボードはページの下にあるので、下へスクロールして開きます。ワークスペースに入っただけではエフェクトのエンジンとデバイスの確認（probe）だけで、モニタリングは自動では開始しないため、エフェクト領域の「モニタリング開始」を押してください。Android / iOS / Linux / Windows の Looper はエフェクト処理後の音を録音します。モニタリングを開始し、実際のサンプルレートを 48 kHz にする必要があります。
- **スマートベース**：ワークスペースに追加した自動ベースライン。いま弾いているコードを認識し、ドラムマシンの BPM・拍子・キックの位置から、ドラム 1 小節と同長のベースラインを自動作成します。スタイルは「キック追従」「ルート・パルス」「ウォーキングベース」の 3 種、音量は独立、コードが変わるときは次の拍へ配置され、停止するとマイクを解放します。

標準チューニング用チューナー（A4 = 440 Hz / 432 Hz の基準音を選択可能）、メトロノーム、スケール指板、初心者向けコードレッスンもあります。README の翻訳はアプリ画面の多言語対応を意味しません。

## 使い方

1. ソースから起動し、ホームの「即興ワークスペース」カードを開きます。ドラムマシン、Looper、エフェクトボードが 1 つの縦スクロール画面に並んでおり、エフェクトボードは下にあるので下へスクロールします。拍子を選び、その拍子のプリセットを選んで伴奏を開始します。拍子を変えると、その拍子の既定プリセットが読み込まれ、速度と音量はそのまま維持されます。
2. エフェクトを使う場合はギターとヘッドホンを同じオーディオインターフェースに接続し、音量を下げてからモニタリングを開始します。ワークスペースへの入場時のデバイス確認（probe）は無音で、モニタリングは自動で開始しません。音を出すにはページ下部のエフェクト領域で「モニタリング開始」を押してください。デスクトップブラウザーでは、このクリックで音声が有効化され、マイク許可が求められます。
3. エフェクト対応環境では 48 kHz でモニタリングしてから最初のレイヤーを録音します。macOS / Web はマイクを許可し、必要に応じてインターフェースのダイレクトモニターを使ってください。メインボタンを再度押すと録音を終了してループ再生し、もう一度押すと重ね録りできます。
4. 初期キー割り当ては **Space**：録音・重ね録り、**S**：停止・再開、**Z**：直前レイヤーを取り消し、**X**：全消去。設定から変更できます。ウィンドウにフォーカスが必要です。スマート録音は最初のレイヤーのみ対象です。
5. 特定のレイヤーだけを削除するには、レイヤー表示の該当マスの右上にある **×** を押します。残りのレイヤーはループ長と位相を保ったまま再生され、通知バーから削除を 1 回だけ取り消せます。最後の 1 レイヤーを削除するとループを停止しループ長を 0 に戻します。録音中やループの読み込み中は削除できません。

ハウリングや伴奏の再録音を避けるため、ヘッドホンを使用してください。ドラム単体にマイク権限は不要です。録音・チューナー・エフェクトには音声入力の許可が必要です。Android は API 24 以上、Apple 環境はマイク許可、Windows はシステムのマイクアクセス許可が必要です。Linux の直接入力録音には `parecord`、`pactl`、`ffmpeg` が必要です。Web は HTTPS または localhost、マイク許可、音声を有効にするユーザー操作が必要です。

チューナーのページ上部には基準音を切り替えるコントロールがあり、タイトルは「标准调弦 · A4 = 440 Hz」または「标准调弦 · A4 = 432 Hz」と表示されます（画面表示は中国語）。その下のセグメントコントロールで「A4 = 440 Hz」（国際標準基準。目標周波数は通常の設定と同じ）と「A4 = 432 Hz」（自然音準。すべての目標周波数が 440 Hz の場合より約 31.8 セント（音分）低い）を切り替えます。432 Hz では 6 本の弦の目標周波数を 432 / 440 倍で換算します。基準音を切り替えると現在の読み値と自動弦検出の確認状態はクリアされるため、もう一度弦を弾いてください。この選択はセッション内だけで保持され、保存されません（ページを離れるかアプリを再起動すると 440 Hz に戻ります）。対応するチューニングは標準 6 弦（EADGBE）のみで、特殊チューニングと任意の基準音には対応していません。

「哇音 Wah」を追加し、位置ノブで 350–2200 Hz を掃引できます（位置 0–1、初期値 0.5）。共振 Q は 0.5–8（2）、ミックス 0–1（1）、出力 0–1（0.7）。ペダルのスイッチで手動（初期値）／自動を切り替えます。自動では速度 0.1–5 Hz（初期値 1）と深度 0–1（0.8）を表示し、位置を中心に掃引します。Linux / Windows のデスクトップ版とデスクトップブラウザーでは、ゲームパッドのアナログトリガーを任意でワウ位置のエクスプレッションペダルとして使えます（下記参照）。Android / iOS / Linux / Windows 共通 DSP で、実機の音質は未検証です。

「移調」を追加すると、ギター全体サウンドを最大 12 半音まで上下にシフトできます（移調ノブは −12〜+12 半音、初期値 0 は原音）。ミックス 0–1（初期値 1）でドライとウェットを合成し、0 半音のときはドライ音がそのまま通ります。出力 0–1（初期値 1）で音量を調整します。アルゴリズムは約 30 ミリ秒のリングバッファを 2 本のクロスフェード読み出しヘッドで読む方式のため、ウェット音がドライ音より約 30 ミリ秒遅れ、金属的な響きになります。タイムストレッチは行わないので演奏速度は変わりません。Android / iOS / Linux / Windows とデスクトップブラウザーで同じ移調 DSP を使用します。移調ノブを −12 と +12 の間で素早く往復するとクロスフェードが中断され、ウェット音に段差状の跳変が出ることがあります。アルゴリズム固有の仕様であり不具合ではありません。

移調の検証（2026-11-05）：静的解析 `flutter analyze lib test` は問題なし、Flutter テスト全 264 项が成功（「移調効果を追加し、3 つのノブを個別に調整できる」項目を新設）、Linux Debug と Web Release のビルドも成功。ネイティブと Web は同一の仕様書の実装で、デスクトップホストの `--test-builtins` とモバイル C++ オフラインテストバイナリがともに成功（内蔵 DSP テスト、モバイルチェーンのウェットキャプチャとライフサイクルテスト）、Node オフライン回帰 13 / 13（新 4 項目）、ブラウザ DSP 自動テスト 38 / 38。0 半音でのサンプル単位の完全直通、±12 半音で基音が 2^(n/12) 倍になること（実測 +12 → 440.4 Hz、−12 → 109.8 Hz、+7 → 328.8 Hz、−5 → 164.9 Hz）、ミックス 0 でドライ音のみ、出力 0 で無音、パラメータ変更時に NaN・クリッピング・クリックが出ないこと、インスタンス間の独立性、44.1 / 48 / 96 kHz とパラメータ極値でも出力が有限であることに対応しています。本ラウンドで Android / iOS / Windows はビルドしておらず（Windows のビルドと検証は 2026-11-08 に実施済み。プラットフォーム表を参照）、実機でのギター演奏の聴感と外付けオーディオインターフェースは未検証です。


モバイル版エフェクトはシステムの現在の音声経路とモノラル入力を使用します。アプリ内経路選択や外部 VST3 はありません。デスクトップ版は入出力・バッファを選択できます。Windows は WASAPI と ASIO のバックエンドを選べますが（ASIO ドライバはインターフェースメーカーのものをインストールして使うもので、同梱ではありません）、入力が複数ある場合は「声卡设置与延迟诊断」カードで各チャンネルのレベルを確認して監視するチャンネルを選べます（既定では信号の最も強いチャンネルに自動追従します）。Bluetooth は低遅延の検証対象出力ではありません。

Windows デスクトップ版エフェクト宿主（2026-11-08）：Windows の Debug ビルドは成功し、`flutter build windows --debug` は `√ Built build\windows\x64\runner\Debug\guitarbook.exe` を出力します。成果物の `build/windows/x64/runner/Debug/` には `guitarbook.exe`、`guitarbook_effects_host.exe`、プラグインの dll、ライセンスが並びます。ホストのオフラインテスト `guitarbook_effects_host.exe --test-builtins` も Windows 上で成功しました（`Built-in DSP tests passed`、`Wet Looper capture tests passed`、`Editable built-in chain audio tests passed`）。ホストプロトコルの JSON 往復で中国語も正常です。Windows で未検証なのは、実機オーディオインターフェースでの入出力、モニタリング、実際の往復遅延と聴感、および第三者 VST3 プラグインの実際の読み込みと聴感です。JUCE のモジュールヘッダーは `build/windows/x64/install/` にインストールされ、アプリには同梱されません。

プラグインスキャン（Linux / Windows デスクトップ版）：デスクトップ宿主に `scan` コマンドを追加し、標準のプラグインディレクトリを走査します。Windows は VST3 ディレクトリ `%ProgramFiles%\Common Files\VST3`、`%ProgramFiles(x86)%\Common Files\VST3`、`%LOCALAPPDATA%\Programs\Common Files\VST3`、VST2 ディレクトリ `%ProgramFiles%\Common Files\VST2`、`%ProgramFiles(x86)%\Common Files\VST2` と `Steinberg\VSTPlugins`、`VSTPlugins` サブフォルダー、および Steinberg の ActivePlugins レジストリを読みます。Linux は `/usr/lib/vst3`、`/usr/local/lib/vst3`、`~/.vst3`、`/usr/lib/vst2`、`/usr/local/lib/vst2`、`~/.vst2` などの標準的な場所を探します。検出されたプラグインごとに名称、メーカー、バージョン、カテゴリー、絶対パス、インストルメント（シンセ）かどうか、ロード可能かどうか、説明文を表示し、「外部プラグイン」パネルに一覧表示してワンクリックで読み込めます。絶対パスを直接入力する方法も残しています。スキャンはホストのサブプロセスで実行されるため、破損したプラグインがホストごと停止させることはありません。VST3 は既存のロード手順でそのまま読み込めます。VST2 は既定では一覧表示のみです。JUCE 8 で VST2 SDK が削除されたため、VST2 を実際に読み込むには Steinberg VST2 SDK が必要で、ビルド時の CMake オプション `GUITARBOOK_ENABLE_VST2` と `GUITARBOOK_VST2_SDK_DIR` で有効化できます（この経路は本機未検証）。ウェブ版は VST3 プラグインもプラグインスキャンも対応しません。

Linux のエフェクト宿主は**システムの既定入力をそのまま使用**し、入力元を推測して切り替えることはしません。PipeWire は Focusrite Scarlett のようなインターフェイスを `Input 1 Inst/Line`、`Input 2 Mic`、ループバックの `Monitor Input 3+4` という別々のノードに分割するため、既定入力がギターを挿したジャックとは限りません。既定入力がマイクやループバックを指していると、アプリはギターではなくそのノードを受け取ります：ダイレクトモニターでは音が聞こえても、ソフトウェアには無音が届きます。その場合はページに「没有收到任何输入数据」と表示されるので、システムの既定入力をギターの Inst/Line ノードに変更し（本機では `wpctl set-default 65` で `Input 1 Inst/Line` を選択）、再接続の操作を押してください。この案内は**完全なデジタル無音が 3 秒続いた場合のみ**表示され、演奏中の休符では出ません。2026-11-03 の実測：既定入力がループバックのときは全サンプルが 0 で `inputPeak` も 0 のまま；`Input 1 Inst/Line` に切り替えると無音時のノイズフロアが 1.2e-4–1.9e-4 になり、6 秒間案内は表示されませんでした。

## ゲームパッドのトリガーによるエクスプレッションペダル（Linux / Windows / デスクトップブラウザー、2026-11-03 Linux 再接続ループ修正）

Linux / Windows のデスクトップ版とデスクトップブラウザーでは、ゲームパッドのアナログトリガーをワウのエクスプレッションペダルとして使えます。初期状態は無効です。「哇音 Wah」を追加し、ペダルボード下の「ゲームパッドのトリガー → ワウペダル」カードを有効にして、左右のトリガーと対象のワウを選び、必要に応じて反転とレンジのキャリブレーションを行います。トリガーの読み値は 25 ms 間隔に間引いてワウの位置パラメーター（350–2200 Hz）へ書き込みます。対象のワウが手動モードで、モニタリング中かつトリガー読み値がある場合のみ書き込み、自動モード・停止中・チェーンにワウがない・対象未選択の場合は書き込まずにカード内で理由を示します。スイッチを切るかページを離れると入力デバイスを解放します。

**修正版に切り替えた後はホットリスタートまたはアプリの再起動が必要です**：ホットリロードでは実行中の isolate のコードは置き換わりません。

トリガーの読み込みは環境ごとに異なります。

- **Linux デスクトップ版**は `/dev/input/event*` を直接読みます。`/proc/bus/input/devices` からアナログトリガー軸を持つゲームパッドを探し、ホットプラグ時の再接続に対応し、取得できればドライバーの実際の軸レンジ（多くは 0–255 または 0–1023）を読みます。多くのデスクトップセッションでは udev の `uaccess` ルールによりログイン中のユーザーへ自動で権限が与えられます。本機（Ubuntu 26.04 仮想マシン）では 2026-11-03 時点で現在のユーザーが ACL 経由で `/dev/input/event20` を読め、open も正常だったため、権限は今回の故障原因ではありませんでした。`getfacl` に該当ユーザーの項目が無い場合のみ、`input` グループへ追加（`sudo usermod -aG input $USER` の後に再ログイン）するか、コントローラー用の udev ルールを追加してください：`/etc/udev/rules.d/99-gamepad.rules` を新規作成して `KERNEL=="event*", SUBSYSTEM=="input", MODE="0660", TAG+="uaccess"` を記述し、`sudo udevadm control --reload-rules && sudo udevadm trigger` を実行します。Flatpak / Snap のサンドボックスは `/dev/input` を遮断する場合があります。**`event*` が権限で開けない場合は旧式 joystick インターフェイスへ自動的に切り替わります**（`/dev/input/js*` は既定 `0664` で、`input` グループなしでもどのユーザーでも読めます）：カーネルは軸値を -32767..32767（0 が中央）に変換するため、0–255 に換算してからワウを駆動します。evdev が開けるときは常に evdev を優先します（ドライバーの実際のレンジが分かるのは evdev だけだからです）。Linux の読み取りは独立した isolate で非ブロッキング `open` + `poll` をポーリングします。`poll` がシグナルで中断された（`EINTR`）場合は残り時間で再試行し、`read` は EOF を読んだときだけ切断とみなし、`EAGAIN` や空読みではポーリングを続けます。
- **Windows デスクトップ版**は XInput で左右のトリガー（0–255）を読み、XInput 対応（Xbox 系）のコントローラーのみ認識します（この Windows 入力層は未ビルド・未実行です）。PlayStation のコントローラーは事前に Steam Input や DS4Windows でマッピングが必要です。
- **デスクトップブラウザー**はブラウザーの Gamepad API を使い、標準ゲームパッドマッピングの 6 番目（L2）と 7 番目（R2）のボタンの模擬量（ブラウザーは 0–1 に正規化し、ここでは 0–255 に換算）を読みます。ブラウザーは通常、ユーザーがゲームパッドのボタンを押すまではデバイスをウェブページに渡しません。またページは前面に置いておく必要があります（背景タブではタイマーが間引かれます）。ゲームパッドが見つからない場合は、カードが 3 つの手順を直接表示します：ゲームパッドのボタンを押す → ウェブページを前面に保つ → Linux ではブラウザーが `/dev/input/event*` を読めるようにする（`input` グループへ追加するか udev の uaccess ルールを追加、Chrome の公式ルールが無い場合もブラウザーはゲームパッドを見られません）。標準マッピングにないコントローラー（トリガーがデジタルボタン）は名称を明示してエラー表示します。

**まず読み取り権限を確認しますが、今回の故障は権限ではありません（2026-11-03 実測）**：`event*` ノードの既定は `0660 root:input` で、`input` グループ外のユーザーは通常読めません。ただし systemd の 70-uaccess ルールは seat0 でログインしたユーザーへ uaccess タグを付け、xpad 系の `event*` には `ID_INPUT_JOYSTICK` も付くため、多くのデスクトップセッションでは元から読めます。本機では現在のユーザーが ACL 経由で `/dev/input/event20` を読め（`getfacl /dev/input/event20` で確認可能）、デバイスはオンラインで open も正常でした。権限を原因とする以前の結論は撤回します。ブラウザー版もブラウザープロセス自身が `/dev/input` を読む必要があります（Chrome は公式 `60-chrome-devices.rules` が無いとゲームパッドを列挙できず、snap 版 Firefox は joystick インターフェース接続済みで通常そのまま動きます）。`getfacl` に現在のユーザーの項目が無い場合のみ、以下で権限を付与します：uaccess ルールは再ログイン不要、`input` グループへの追加は再ログインが必要です。Flatpak / Snap のサンドボックスも `/dev/input` を遮断する場合があります：

## スマートベース（2026-11-05）

スマートベースはワークスペースの自動ベースラインです。いま弾いているギター入力を聞き、コードを認識して、ドラムマシンの速度・拍子・キックの位置からベースラインを自動作成します。あなたはコードを弾くだけです。

パネルはドラム／Looper とエフェクトボードの間にあり、次の要素を持ちます。

- **開始／停止**：「スマートベースを開始」で入力を待ち、ベースを再生します。もう一度押すと停止し、マイクを解放します。
- **現在のコード**：認識したコード（Cmaj、Am、G7 など）を表示します。連続 2 回の解析が一致してから切り替わるため、演奏の切れ目でも表示がちらつきません。
- **スタイル**：キック追従、小節ごとに固定位置でルートを鳴らすルート・パルス、1 拍ごとにコード音を進めるウォーキングベース。
- **音量**：0–100 %。ドラムマシンと Looper とは別に調整できます。

使い方：

1. 先にドラムマシンで拍子・プリセット・速度を決めてください。ベースラインはドラムマシンの現在の BPM・拍号・キックの位置から作られます。
2. コードが変わっても拍の途中では切り替わりません。次の拍へ繰り越されます。ベースループはドラム 1 小節と同長でサンプル単位で一致するため、ずれません。ドラムとの位相は 400 ms ごとに確認し、120 ms を超えたら自動で合わせ直します。
3. Android / iOS / Linux / Windows ではエフェクト処理後の音（ウェット）を聞くため、先にエフェクト領域で 48 kHz のモニタリングを開始する必要があります。macOS とブラウザーはマイクのドライ音を使用します。ブラウザーでは HTTPS または localhost、マイク許可、音声を有効にするユーザー操作も必要です。
4. スマートベースは全体録音と Looper と同じ入力経路を使うため、マイクを追加で開きません。動作中はページ上部のマイク表示が点灯します。ヘッドホンを推奨します。
5. 入力が無音の場合、またはノイズが大きすぎる場合は、コードを認識せず音も出しません。直前の結果を保持します。

制限：認識は 1 コードずつで、複数コードの同時認識や旋律追従はありません。ベースは正弦に倍音を重ねた合成音（ルート音は E1–A2）で、サンプリング音源ではありません。スマートフォンでは認識と合成に多少の演算負荷がかかります。認識精度には限りがあり、合成音での回帰テストでは 16 個のコードのうち 10〜13 個でルートとコード性を同時に当てられました（音域によります）。誤りはルートが約 130 Hz 以下の低位のコードと sus4・属七など性質の紛らわしいコードに集中し、低域では基音が混ざり合うため倍音から推測するしかありません。

## 即興演奏の全体録音

ワークスペースでドラム、Looper の再生、演奏入力を 48 kHz モノラル WAV に録音できます。8–128 MiB（初期値 32 MiB、約 5.8 分）を選び、容量が一杯になると最も古い音声を上書きします。停止後は試聴・保存できます。新しい録音は未保存の音声を置き換えます。バックグラウンドで停止し、退出時に未保存音声を消去します。エフェクト対応環境では 48 kHz のモニタリングが必要です。演奏はエフェクト後・モニター音量前、ドラムと Looper は各再生音量で録音します。ヘッドホンを使い、大音量によるクリッピングに注意してください。ドラムと Looper は録音開始時の最初のブロックで再生位相を固定し、以降は実際に録音した入力フレームで進め、エンジンと入力クロックのずれを 1 ブロックあたり 0.2%（約 3 cent）までゆっくり補正します。エンジン位置が 100 ms を超えて跳ぶ場合（再定位・再生のやり直し）だけ新しい位置に合わせ直します。これにより、音声バッファー単位（ネイティブで 512 フレーム、約 10.7 ms）に量子化された再生位置を毎ブロック取り直すことによるタイムラインの分断を防ぎます。複数エンジンはハードウェア同期しておらず、最初のブロックの固定ずれは最大 1 バッファー残ります。

保存先はアプリのドキュメント内 `Guitarbook Recordings` で、パスを表示します。iOS は「ファイル」からアクセス可能に設定しています。Android は現在アプリ専用領域で、アンインストール時に削除され、共有・保存先選択はありません。Web はブラウザーでダウンロードします。試聴・書き出しには録音容量以外のメモリも必要です。実機音声・ファイルアクセスは未検証です。自動検証の最新状況は中国語 README を参照してください。

## 現在の制限

ドラムと Looper は独立したループです。自動テンポ同期、クオンタイズ、タイムストレッチはありません。未保存の音声はローカルメモリに保持し、退出時に消去します。全体のミックスは WAV 保存できます。アップロードせず、エフェクトチェーンやデバイス設定は永続保存しません。バックグラウンドに移ると停止し、復帰時に自動再開しません。MIDI やバックグラウンドのグローバルショートカットも未対応です。ゲームパッドはワウのエクスプレッション専用で、Looper のペダル割り当てには使いません。

アンプはオリジナルのアルゴリズムと簡易キャビネットフィルターで、IR 畳み込みやオーバーサンプリングはありません。外部プラグインは OS・CPU に対応するものを別途用意してください。デスクトップ宿主は導入済み VST3 / VST2 プラグインをスキャンしますが、VST2 は一覧表示のみで、Steinberg VST2 SDK なしでは実際に読み込めません（ビルド時の CMake オプション `GUITARBOOK_ENABLE_VST2` と `GUITARBOOK_VST2_SDK_DIR`、この経路は本機未検証）。インストルメントはスキャン結果で識別するだけです。エフェクトチェーン、プラグインのパラメーター、デバイス設定は依然として永続保存しません。表示されるドライバー遅延は物理的な往復遅延の実測値ではありません。実機の音質、USB インターフェース互換性、長時間の安定性は引き続き検証が必要です。

ドラムマシンのグリッドは 1 小節固定で、複数小節・自動フィル・サンプル取り込み・プリセット保存は未対応です。ドラム種の追加 要否は未確定です。Looper は 1 テイク 1 ループで、最大 30 秒・6 レイヤーまでで、レイヤー単位の長さ調整や音量調整はありません。

スマートベース：ドラムと Looper は独立したループのままで、スマートベースだけがドラムマシンとサンプル単位で同期します（Looper とは同期しません）。認識は 1 コードずつで、サンプリング音源ではなく合成音を使い、6 プラットフォームでの実演奏の聴感は未検証です。認識精度には限りがあり、合成音での回帰テストでは 16 個のコードのうち 10〜13 個でルートとコード性を同時に当てられ、誤りは最低音域に集中しています。

## ソースから実行

現在、公式インストーラーや公開 Web アプリはありません。Flutter と `pubspec.yaml` の Dart 条件（現在 `^3.12.0`）、対象環境の開発ツールを用意します。

```bash
flutter doctor
flutter pub get
flutter devices
flutter run -d <device-id>
```

デスクトップは `linux`、`windows`、`macos`、Web は `chrome` を指定できます。iOS は macOS と Xcode が必要です。ネイティブエフェクトには CMake / C++ ツールが必要で、Android は NDK と CMake 3.22.1 も必要です。JUCE 8.0.12 は git クローンではなく、タグ `8.0.12` を固定し SHA-256（`dec1a8ba…cf102`）を検証するソースアーカイブとして取得します。共有キャッシュにアーカイブを `.dart_tool/guitarbook-native/downloads/`、展開済みのソースを `.dart_tool/guitarbook-native/JUCE-8.0.12/`（iOS 用の補助スクリプト `tool/prepare_ios_effects.sh` と同じディレクトリ）に置きます。展開済みのコピーがあればビルドがそのまま再利用するため、再ビルドやオフラインビルドでネットワークは不要で、Android / iOS も同じアーカイブからビルドします。ミラーや制限のあるネットワークでは `-DGUITARBOOK_JUCE_URL=<ミラー URL>` で取得先を指定できます（SHA-256 の検証は変わらず、ミラーは同一のアーカイブを用意する必要があります）。キャッシュの外に置くローカルソースは `-DFETCHCONTENT_SOURCE_DIR_JUCE=/絶対パス/JUCE` で指定できます。プラグインスキャンが検出する VST2 は一覧表示のみです。JUCE 8 で VST2 SDK が削除されたため、VST2 を実際に読み込むには Steinberg VST2 SDK が必要で、CMake の設定時に `-DGUITARBOOK_ENABLE_VST2=ON` と `-DGUITARBOOK_VST2_SDK_DIR=<VST2 SDK のフォルダー>` を指定して有効化します（この経路は本機未検証）。JUCE の AGPLv3 / 商用ライセンスを含む依存関係のライセンスに従ってください。

Windows のビルドで `CUSTOMBUILD : error : RPC failed; curl 52 Empty reply from server`、`Failed to connect to github.com:443`、`Failed to clone repository: 'https://github.com/juce-framework/JUCE.git'` が表示される場合、依存の取得が従来の git クローン方式のままであることを示します。git は Windows のシステムプロキシを使いません。ブラウザーはローカルのプロキシ経由で GitHub に到達できますが、git と CMake は到達できません。次のどちらかを実施してください。補助スクリプトを一度実行する（システムプロキシ経由でダウンロードし、SHA-256 を検証して共有キャッシュへ展開します）、または `-DGUITARBOOK_JUCE_URL=` でミラーを設定する。

```powershell
pwsh -File tool/prepare_juce_sources.ps1
pwsh -File tool/prepare_juce_sources.ps1 -Proxy http://127.0.0.1:10808
```

旧い git ベースの定義が残した `build/windows/x64/_deps/juce-subbuild` は依然としてクローンを試みるので、再設定の前にビルドフォルダーの `_deps` を削除してください。

```powershell
Remove-Item -Recurse -Force build/windows/x64/_deps
```

どちらの対処も依存の取得の修正のみを対象とするもので、ビルド結果を示すものではありません。

### Windows のビルド失敗（2026-11-08 に修正）

Windows のビルドを妨げていた失敗は原因の異なる 2 つで、現在のリポジトリではどちらも修正済みです。最新のツリーであれば手動の回避策は不要です。

**1. MSVC のソース符号化**：ソースは BOM なしの UTF-8 で、MSVC は `/utf-8` を渡さない限りシステムコードページ（936 / GBK）で読み込むため、中文字面量が壊れて `error C2001: 字符串字面量中的换行符`（英語ロケールでは "newline in string literal"）が発生していました。`native/effects_host/CMakeLists.txt` と `native/mobile_effects/CMakeLists.txt` に `if(MSVC) add_compile_options(/utf-8) endif()` を追加し、ホストの実行時出力も UTF-8 のままにしています。

**2. CMake の install 段階**：Flutter のテンプレートは `CMAKE_INSTALL_PREFIX` にジェネレーター式 `$<TARGET_FILE_DIR:guitarbook>` を設定していましたが、JUCE サブプロジェクトはモジュールヘッダーを相対 DESTINATION でインストールするため、install スクリプト実行時にまだ展開されていないプレフィックスと結合され、`file INSTALL cannot make directory ... Invalid argument` → `error MSB3073` → `Error: Build process failed.` になっていました。`windows/CMakeLists.txt` は実在する絶対プレフィックス（`${CMAKE_CURRENT_BINARY_DIR}/install`）を維持し、アプリ本体のインストール先を絶対ジェネレーター式 `${BUILD_BUNDLE_DIR}` に変更しました。`native/effects_host/CMakeLists.txt` のホスト用インストールルールにも同じ絶対ディレクトリを渡します。

古いビルドツリーに以前のキャッシュが残っている場合は、再設定してください。

```powershell
cmake -S windows -B build/windows/x64
```

ビルドツリーを削除して作り直す場合は次のとおりです。

```powershell
Remove-Item -Recurse -Force build/windows/x64
flutter build windows --debug
```

`build/windows/x64/install` は CMake が JUCE ヘッダーをインストールした先だけで、アプリには含まれません。削除しても問題ありません。

ビルド成功後に別の症状が出る場合もあります。`flutter run -d windows --debug lib/main.dart` はビルドしてアプリを起動でき（`Using the Impeller rendering backend (OpenGLESSDF)`）、その後で flutter ツールが `Finished with error: _createDevFS: (-32603) Internal error` / `_createDevFS: Unexpected exception:PathAccessException: Creation of temporary directory failed, path = 'C:\Users\<ユーザー名>\AppData\Local\Temp' (OS Error: アクセスが拒否されました。, errno = 5)` を報告して `App failed to start` で終了します。これはアプリ側の不具合でも %TEMP% の ACL 拒否でもありません。ビルド出力に `Mandatory Label\Low Mandatory Level`（低整合性レベル）の強制ラベルが付いていると（制限付きサンドボックス内でのビルドでよく起こります）、アプリが低整合性で起動し、Windows が低整合性プロセスによる中整合性ディレクトリへの書き込みを禁じているため、アプリ内の Dart VM service（`createTempDirCallback` → `Directory.systemTemp.createTemp`）が DevFS ディレクトリを作れなくなります。ビルドツリーの強制ラベルを引き上げて再ビルドすれば直ります。

```powershell
icacls "build\windows\x64\runner\Debug" /setintegritylevel "(OI)(CI)M" /T
icacls . /setintegritylevel "(OI)(CI)M"
```

`/T` はサブファイルとサブディレクトリに再帰的に適用され、`(OI)(CI)` によって以降の新規ファイルがラベルを継承します。2 番目のコマンドをリポジトリルートに実行すると `lib` と `build`、以降のビルド出力が中整合性ラベルを継承します。ラベルを変えたくない場合は、`TEMP` / `TMP` を同じ低整合性レベルのディレクトリ（リポジトリ内の `build\tmp` など）に向けて回避できますが、その場合でもアプリ自体は低整合性のままです。検証（2026-11-08）：修正後、系统 %TEMP% を一切リダイレクトせずに `flutter run -d windows --debug` が `Syncing files to device Windows... 69ms` と `A Dart VM Service on Windows is available at: http://127.0.0.1:56071/mdI6FVvi8Z4=/` に到達し、`_createDevFS` エラーは出力されませんでした。

Windows 低遅延: ASIO（2026-11-08）。デスクトップ用エフェクトホストは `JUCE_ASIO` を定義しておらず、JUCE が ASIO バックエンドをコンパイルしないため、デバイス選択には `Windows Audio` と `DirectSound` しか現れず、Windows ではシステムミックス経路を通этомуレイテンシ偏高でした。「ASIO には別途 SDK が必要」という古いコメントは既に古く、JUCE 8 は Steinberg ASIO SDK のインタフェースヘッダーを同梱しているため `JUCE_ASIO=1` だけでビルドできます。`native/effects_host/CMakeLists.txt` で Windows のみ有効化し、ホストの `status` に `deviceTypes` と `asioDrivers` を追加、エフェクトページは「声卡设置与延迟诊断」カードに両方の一覧と手順を表示します（ASIO ドライバはインターフェースメーカーのものをインストールして使うもので、同梱ではありません）。検証（2026-11-08）：本機では `deviceTypes` に `ASIO`、`asioDrivers` に `Focusrite Thunderbolt ASIO` と `Focusrite USB ASIO` が報告され、ASIO SDK のライセンスは `data/licenses/ASIO-SDK-LICENSE.txt` として同梱されます。ASIO に切り替えた後の実測レイテンシとモニタリングの聞こえ方は、実機での測定が未了です。

入力チャンネルの選択と自動追従（2026-11-08）。ホストは常に 1 入力でデバイスを開いており（`devices.initialise(1, 2, nullptr, true)`、JUCE の `useDefaultInputChannels = true`）、コールバックでも 1 番目の入力を固定で監視していました。ギターは通常インターフェースの 2 番目の入力（Scarlett の Inst 1）に挿すため、監視対象は完全なデジタル無音でした。デバイス選択ウィンドウはデバイス種別の変更時にチャンネル数を 1 に戻すため、ASIO に切り替えても解決しませんでした。修正後は最大 4 入力まで開き（明示的なチャンネルマスクを使い、ドライバーが受け付けない幅にはフォールバック）、コールバックで各チャンネルのピークを測り、既定では 1.5 倍のヒステリシス付きで信号の最も強いチャンネルに追従します（ページで手動固定も可）。`status` に `inputChannelNames` / `inputChannelLevels` / `activeInputChannel` / `autoInputChannel` を追加し、`inputChannel` コマンドで自動／固定を切り替えます。検証（2026-11-08）：本機の Focusrite USB で `status` は `"inputChannels": 2`、`"inputChannelNames": ["Input channel 1", "Input channel 2"]` を報告（以前は 1 入力のみ）、Windows Debug ビルドと `flutter run -d windows --debug` は成功。ギターを挿した状態での実測レベルと自動追従の選択結果は実機での確認が未了です。

| --- | --- |
| `flutter pub get` → `flutter analyze` → `flutter test` | ローカル開発と同じ検査。いずれかが失敗すると公開しません |
| `flutter build web --release --base-href /guitarbook/` | Pages のサブパスに合わせて参照リンクを生成するため、リポジトリ直下以外でもアセットが 404 になりません |
| `--no-web-resources-cdn` | CanvasKit レンダラーを成果物一起に同梱し、実行時の `gstatic.com` CDN 依存を無くします（成果物のサイズは増えます） |
| `actions/deploy-pages` | GitHub Pages に公開し、公開先 URL を表示します |

注意：

- Settings → Pages の Source は GitHub Actions に設定済みです（2026-11-09）。設定がリセットされた場合は、`main` への push で起動した実行が「Configure GitHub Pages」ステップで失敗します（`Get Pages site failed … Not Found`）。再設定してから実行をやり直してください。
- マイクは HTTPS または localhost でのみ許可されます。GitHub Pages の `https://` URL は条件を満たしますが、初回アクセス時にブラウザーの許可が必要です。
- ページに Service Worker が含まれるため、公開直後は古い版がキャッシュされることがあります。最新版が表示されない場合は強制再読み込み（Ctrl / Cmd + Shift + R）してください。
- 実行時の中文字体は Flutter エンジンが `fonts.gstatic.com` からフォールバックとして取得します。同ドメインに接続できない環境では中文が豆腐（□）表示になるため、完全にオフラインで使うにはアプリ内に中文字体を同梱する必要があります。
- 公開されるのは `main` のビルド結果のみで、公開リポジトリではページが誰でも閲覧できます。

## PR 歓迎！

ドラムのリズム・音色、Looper の操作や同期、エフェクト DSP、プラットフォーム対応、アクセシビリティ、翻訳、ドキュメントへの貢献を歓迎します。大きな設計変更は、先に Issue で相談してください。

1. [AGENTS.md](AGENTS.md) と [機能設計](docs/FEATURES.md) を確認してください。
2. `flutter analyze` と `flutter test` を実行し、音声関連の変更には該当するネイティブのビルド・テスト結果も添えてください。
3. 動作が変わる場合は関連する各言語の README と機能設計を更新し、確認済みの環境と未検証の項目を明記してください。

デバイスの検証報告も歓迎します。OS、インターフェース、サンプルレート・バッファ、再現手順、結果を記載してください。第三者のプラグイン、利用制限のある音素材、個人の録音は含めないでください。
