# 吉他宝典（guitarbook）

[简体中文](README.md) · [English](README.en.md) · [日本語](README.ja.md)

> 为吉他即兴而做：用鼓机铺好节奏，用 Looper 叠出乐句，用效果器塑造音色。

## 鼓机 × Looper × 效果器

- **鼓机**：12 种风格预设，底鼓、军鼓、踩镲三轨 16 步编辑，30–240 BPM、摇摆、分轨静音与独立音量。
- **Looper**：最长 30 秒首层、最多 6 层叠录，支持撤销、智能首层录音，以及键盘 / 模拟键盘的 USB 脚踏绑定。
- **实时效果器**：Fuzz、压缩、混响、过载、延迟、哇音与四种原创风格箱头，最多 8 节串联，可拖动排序、独立调参和旁通；Linux / Windows 可加载 VST3，还可用游戏手柄的线性扳机控制哇音位置（表情踏板）；电脑端浏览器提供同一批内置效果（本次变更实现，自动化整页实测通过；不支持 VST3 与湿声 Looper；2026-11-03 真实声卡环回实测本机网页端往返约 67–75 ms，页面侧有效项是 `latencyHint: 0`（省约 8 ms）、Chrome 启动参数 `--audio-buffer-size=128`（省约 21–27 ms，可到约 45 ms）与内置的低延迟插入式采集（`MediaStreamTrackProcessor`，再省约 4 ms，可到约 42 ms），再往下需改用桌面原生宿主），并新增用浏览器 Gamepad API 读取手柄线性扳机。
- **一起即兴**：从首页“鼓机”进入即兴工作台，同页操作三件工具、分别调节音量。Android / iOS / Linux / Windows 可将效果链处理后的声音录入 Looper（需先监听，实际采样率为 48 kHz）。

鼓机与 Looper 已接入六个平台；实时效果器支持范围为 Android / iOS / Linux / Windows 与电脑端浏览器（浏览器版为本次变更实现、自动化整页实测已通过，并已完成真实声卡环回延迟实测；macOS 暂不支持），其中哇音的表情踏板（游戏手柄线性扳机）在 Linux / Windows 桌面版与电脑端浏览器提供（Web 端为本次新增，基于浏览器 Gamepad API）。鼓机与 Looper 各自循环，**目前没有自动节拍同步、量化或时间拉伸**。Looper 分层仅留在内存，离页清空；工作台新增整段循环录音，可保存混音 WAV，见下文。当前需从源码运行，构建通过与真机音频验证的区别见下方平台表。

## 当前进度

已实现 Looper 叠录、鼓机、工具首页、零基础和弦练习、音阶指板、节拍器页面和标准六弦吉他调音器：自动识别所拨空弦、支持手动选弦，实时显示平滑频率、音分偏差、动画指针及稳定调准反馈。麦克风采集与各平台实际运行尚待设备验证，尚未提供正式安装包或在线访问地址。实时效果器的哇音还可用游戏手柄线性扳机控制位置：Linux / Windows 桌面版与电脑端浏览器（本次新增 Gamepad API 支持）均已接入。2026-11-03 修复了 Linux 端在 Dart VM 采样分析器（Flutter debug 构建默认开启）下每隔约 1 秒出现一次「已连接 → 已断开」循环的问题：分析器的 SIGPROF 会打断阻塞中的 `poll(2)` 返回 `EINTR`，旧代码把 -1 当成手柄断开；现已加入 EINTR 重试、修正 `open()` 的 `O_NONBLOCK` 参数、区分 EOF 与空读、重新启用时清空去重缓存。静态分析通过，相关 40 项测试通过；CLI 探针在 profiler 开启时只输出一条 `status=ready`（Flydigi Apex 5，量程 0–255）。GUI 端到端已在 profiler 开启的 Debug 构建中验证：打开开关即显示「已连接：Flydigi Apex 5」，连续 35 秒采样无回落循环、进程内恰好 1 个 `/dev/input/event20` fd，关→开 3 次均能恢复连接。切换到修复版本后需热重启或重启 App（hot reload 不会替换已运行的 isolate 代码）。真实扳机轴数值与哇音扫频听感仍待用户实测。电脑端浏览器版实时效果器（内置效果器）为本次变更：DSP 内核已通过 Node 离线回归（9 / 9）与 Chrome 156 无头端到端验证（38 / 38），Flutter Web 后端已落盘，静态分析与桌面 Chrome 整页自动化实测（29 / 29）通过；2026-11-03 完成真实声卡环回延迟实测两轮：本机网页端默认参数往返约 67–75 ms（浏览器只报输出侧 baseLatency 2.7 ms 与采集 21.3 ms，`outputLatency` 在 Linux Chrome 恒为 0），页面侧有效项是 `latencyHint: 0`（省约 8 ms）与 Chrome 启动参数 `--audio-buffer-size=128`（采集缓冲 21.3→2.7 ms，往返约 45 ms，省约 21–27 ms，脚本 `tool/web_low_latency.sh`）；PipeWire quantum 在本机 Chrome 环回上无稳定收益，剩余约 45 ms 在 Pulse/ALSA 播放路径与 USB/硬件，要进到 20 ms 以内需改用桌面原生宿主；延迟诊断面板已按此区分「浏览器报告输出侧 / 采集侧」与「需环回实测的往返延迟」并给出分级优化建议。真实吉他听感仍待验证。

节拍器已改为音频引擎连续循环播放，按采样帧生成拍音；Linux Debug 与 Web 构建通过，实际音频延迟和各平台设备运行仍待验证。

功能的当前设计和实现状态见 [最新功能设计](docs/FEATURES.md)。开发时需遵循 [项目开发约定](AGENTS.md)，随功能变化同步维护文档。

全应用统一使用暖纸色背景、深青绿操作色，录音使用陶土色、调准使用绿色，并保留文字或图标提示。自动跟随系统明暗主题，统一卡片、按钮与输入样式。

## 实时效果器（Android / iOS / Linux / Windows / 电脑端浏览器，2026-11-01）

已接入 Android / iOS / Linux / Windows 的六类内置单块和四种箱头模拟代码；Linux / Windows 另支持 VST3。移动端使用应用内原生音频引擎；macOS 暂不支持，页面显示平台限制。电脑端浏览器提供同一批内置效果（本次变更实现，自动化整页实测通过，真机听感待验证，见下文“电脑端浏览器版效果器”），不支持 VST3 与湿声 Looper。四个平台可在即兴工作台中配合鼓机、Looper 使用，Looper 默认录下效果器处理后的声音（湿声）。构建与设备验证状态分别记录，代码接入不代表已完成真机验证。

1. 吉他连接声卡的乐器输入，耳机接同一声卡；从首页进入“实时效果器”即自动尝试监听，空链输出干声。请先降低声卡耳机音量。启动失败时检查设备/权限后点击“开始监听”重试。电脑端浏览器需先点击“开始监听”，由该次点击解锁音频并申请麦克风权限。
2. 桌面需要更换设备时，先停止监听，点击“声卡与输入通道”，在独立设置窗口选择一个吉他输入通道、立体声输出、采样率及缓冲大小。Windows 使用本机可用的 WASAPI 等后端，本轮不包含 ASIO SDK；Linux 后端以设备设置实际列表为准。
3. 直接点击“Fuzz 法兹 / 压缩 / 混响 / 过载 / 延迟 / 哇音 Wah”或四种箱头按钮添加内置效果，无需下载插件。Linux / Windows 也可输入适配当前系统和 CPU 架构的 `.vst3` 插件绝对路径，点击“加载插件”。Linux 示例：`/home/you/.vst3/MyEffect.vst3`；Windows 示例：`C:\Program Files\Common Files\VST3\MyEffect.vst3`。Linux 不能直接加载 Windows 插件。插件需自行安装，本项目不附带第三方音色；同一插件包有多个类型时加载第一个类型。
4. 页面顶部查看监听状态、输入/输出电平与削波提示；手动停止后可点击“开始监听”恢复。输出音量默认 50%，可在 0–100% 调节；关闭声卡直通监听可避免同时听到原始干声。
5. 内置和 VST3 可混合串联，合计最多 8 节；同一种内置效果可重复添加，各自参数独立。效果器板按真实单块的右进左出连接：右侧吉他输入 → 编号 1…N → 左侧输出；侧面插孔、跳线和箭头展示实际串联关系。鼠标或触摸拖动单块顶部把手到目标单块位置排序（目标高亮，松开后插入，其他单块相对顺序保留）；窄屏拖至板边缘自动横向滚动，放到板外取消。也可点击前移/后移箭头排序、关闭图标移除；按金属脚踏开关切换旁通，旁通时状态灯熄灭，连接保留。监听时可自由添加、加载、移除、排序、旁通及转动参数旋钮，也可打开 VST3 参数窗口，无需反复停止/启动。结构切换可能短暂断音，旁通/移除会截断尾音。点击停止关闭音频设备；离页释放插件与引擎。最小化或进入隐藏/暂停状态停止监听，恢复后手动启动。
6. Linux / Windows 桌面版与电脑端浏览器还可把游戏手柄的线性扳机当哇音表情踏板：先添加“哇音 Wah”，在效果器板下方“手柄线性扳机 → 哇音踏板”卡片启用，选择左/右扳机和目标哇音，再踩扳机扫频。默认关闭；哇音处于自动扫频、还没开始监听或没读到扳机读数时不会写入位置，卡片会提示原因。浏览器端通过 Gamepad API 读取（需要页面在前台且用户与页面有过交互），Linux / Windows 桌面端直接读取系统输入设备。


移动端使用方法：先将兼容的 USB 音频接口接入手机，耳机接同一接口，首次监听或工作台检测时允许录音权限。使用系统当前音频路由及系统单声道输入；没有外接接口时使用系统麦克风。请使用有线耳机避免扬声器反馈，蓝牙不作为低延迟验收输出。Android 使用 Oboe，iOS 使用 RemoteIO，Android 使用系统原生采样率，iOS 请求 48 kHz；两端均请求低缓冲。实际采样率、回调块长及 Android 输出队列大小以诊断为准。停止监听后可调整缓冲请求，系统可能采用不同值。实际采样率不是 48 kHz 时，Looper 明确拒绝湿声录音。

Android / iOS 不提供外部 VST3、桌面声卡设置窗口或应用内路由选择；切换系统路由或插拔声卡后需手动重新开始。进入后台、来电/音频焦点中断会停止监听和未完成录音，回前台不会自动出声。拒绝权限后可在系统设置授权并重试。Android 暂不提供驱动往返延迟报告，两端暂不提供音频负载统计；不将缺失指标显示为实测零延迟。

移动端首次原生构建需联网下载 JUCE 8.0.12，Android 使用该 JUCE 版本随附的 Oboe 1.9.0，并需要 Android NDK 与 CMake 3.22.1。iOS 在现有 Xcode 构建步骤中运行 `tool/prepare_ios_effects.sh`，将 JUCE 源码缓存到 `.dart_tool/guitarbook-native/JUCE-8.0.12`；可提前执行该脚本供离线构建。JUCE 沿用 AGPLv3 / 商业双许可；发布移动端同样需要遵循依赖许可。

内置效果使用基础数字算法：哇音使用带参数平滑的共振带通滤波、Fuzz 硬削波、过载软饱和、立体声联动压缩、算法混响及反馈延迟；箱头使用原创风格算法及可关闭的简易箱体滤波，不复刻特定硬件，不含 IR 卷积或过采样。界面中的输出与反馈以 0–1 数值显示。每块效果器使用彩色金属外壳、螺丝、刻度旋钮、状态灯与金属脚踏开关，以更紧凑的尺寸摆放在纯色深灰效果器板上。旋钮上下拖动调参，点击旋钮打开精细滑块；键盘 Tab 聚焦后用上下键微调、Enter 打开精细调节。窄屏可触摸或鼠标左右拖动，并使用滚动条浏览整块板；默认从输入与第一块开始。VST3 使用独立单块外观，通过“参数窗口”调整实际插件参数。“声卡设置与延迟诊断”和“外部 VST3 插件”默认折叠，展开后可查看详细信息或输入插件路径。可从“压缩 → 过载 → 箱头 → 延迟 → 混响”开始尝试，也可以自由改变顺序。旁通会跳过处理、切断尾音，不做无缝切换。

Linux 默认请求 **48 kHz / 128 帧**；页面可在停止监听时切换 64 / 128 / 256 / 512 帧，实际生效值、每块时长、驱动输入/输出延迟、插件延迟及欠载次数分别显示。先用 128 帧；需要更低延迟可试 64 帧，出现爆音或断续则提高到 256 / 512 帧。驱动打开失败时会尝试较大缓冲并显示回退；不支持的手动值会报错。调整不会清除效果链或改选输入通道。

使用 PipeWire 默认设备时，宿主只在自己的进程内设置 `PIPEWIRE_QUANTUM`，使活动节点请求低缓冲；节点存在期间可能临时改变同一音频图中其他客户端的调度，关闭设备/离页后释放，不写系统配置或服务器 metadata。外部已设置的 `PIPEWIRE_QUANTUM` 优先。原生声卡设置仍可选择直接硬件设备；JACK 仅在构建时找到开发头文件才启用，还需运行中的 JACK 或 PipeWire JACK 兼容库。本机没有 JACK 开发头/兼容库，本轮实际验证的是 ALSA → PipeWire 路线。

Linux 桌面效果器按**系统默认输入**采集，应用内不自动猜选输入源。若系统默认输入被设成声卡的麦克风或回环通道，宿主采到的是回环/麦克风而不是吉他：声音经声卡直通监听能听到，但软件收不到信号。Focusrite 等声卡在 PipeWire 下常被拆成 `Input 1 Inst/Line`、`Input 2 Mic`、`Monitor Input 3+4` 等独立节点，默认输入不一定对应插线接口。出现这种情况时监听中会提示“没有收到任何输入数据”，请先在系统声音设置把默认输入改为吉他所在的 Inst/Line 接口（本机示例：`wpctl set-default 65` 切到 `Input 1 Inst/Line`），再点「重新连接设备」。提示只在连续 3 秒**精确数字静音**后出现，正常演奏的停顿不会触发。2026-11-03 本机实测：默认输入为回环时采集样本全为 0、`inputPeak` 恒 0；改指向 `Input 1 Inst/Line` 后空闲噪声地板 1.2e-4–1.9e-4，6 秒内不再提示。

### 电脑端浏览器版效果器（本次变更实现，自动化整页实测通过）

电脑端浏览器（桌面 Chrome / Edge 为目标）提供与原生端相同的内置效果：Fuzz、压缩、混响、过载、延迟、哇音六类单块与四种原创风格箱头，最多 8 节串联，可调参、旁通、拖动排序、查看输入 / 输出电平并调节输出音量，界面复用同一套拟物单块效果器板。实现方式为 Flutter Web + Web Audio 的 AudioWorklet：DSP 内核是原生 C++/JUCE 算法移植的 JavaScript，运行在浏览器的音频线程里。

使用方式：

1. 吉他接声卡的乐器输入，耳机接同一声卡；先调低声卡耳机音量，并关闭声卡的直通监听，避免干声与效果声叠加。
2. 用桌面浏览器打开应用（需 HTTPS 或 localhost），进入“实时效果器”后点击“开始监听”，并在浏览器弹出的提示中授权麦克风。浏览器要求由用户手势解锁音频，因此必须先点击“开始监听”；若从首页点进来时已经产生过用户操作，页面会直接开始监听并请求麦克风权限；只有在页面从未被操作过的情况下才会提示“浏览器要求用户手势：请再点击一次「开始监听」。”，不会静默失败。
3. 点击效果库里的内置效果即可添加，最多 8 节；效果器板上的旋钮用于调参，金属脚踏用于旁通，拖动单块顶部把手可排序，输出音量在 0–100% 调节。
4. 停止监听或离开页面会释放麦克风；浏览器标签页被隐藏或暂停时也会停止监听，回来后需手动重新开始。

限制（与原生端的差异）：

- 延迟由浏览器与系统音频栈决定，页面能调的只有 AudioContext 的 `latencyHint`。2026-11-03 在本机（Focusrite Scarlett Solo 4th Gen + PipeWire 1.6.2，quantum 1024）用硬件 Loopback 实测「播放 → 采集」往返：默认参数约 67–75 ms，浏览器只报输出侧 baseLatency 2.7 ms 与采集 21.3 ms，`outputLatency` 在 Linux Chrome 恒为 0。把 `latencyHint` 改为数字 0 后省约 8 ms；用 Chrome 启动参数 `--audio-buffer-size=128` 再省约 21–27 ms（往返约 45 ms，仓库脚本 `tool/web_low_latency.sh`）；网页端内置的低延迟插入式采集（`MediaStreamTrackProcessor`，浏览器不支持时自动回退）再省约 4 ms，与旗标叠加后本机约 42 ms。调小 PipeWire quantum（`pw-metadata -n settings 0 clock.quantum 128`）在本机 Chrome 环回上没有稳定收益（Chrome 采集走 ALSA 硬件环回，不经 PipeWire），只对走 Pulse 的桌面端链路可能有效。剩余延迟在 Pulse/ALSA 播放路径与 USB / 硬件上，网页无法再压缩；要进到 20 ms 以内只能改用桌面原生宿主 `guitarbook_effects_host`（64/128 帧块直接读写声卡）。蓝牙耳机不作低延迟验收环境。
- 输出只能走系统默认音频设备，无法在页面内切换输出设备；也无法选择声卡输入通道，输入由浏览器与系统决定；缓冲大小同样由浏览器决定，没有声卡设置窗口。
- 不支持 VST3：网页端没有插件加载与参数窗口，也没有声卡设置窗口。
- 不支持湿声 Looper：网页端的 Looper 录的是干声（原始输入），不是效果链处理后的声音。
- 页面刷新或崩溃会丢失整条效果链（网页端无法像原生那样重新连接宿主进程）。
- 网页端混响是 Freeverb 结构等效实现，与原生 JUCE Reverb 音色不完全一致（未做逐样本对齐）。

当前状态：DSP worklet 与 Flutter Web 后端均已落盘（尚未提交）并通过验证——Node 离线回归 9 / 9、Chrome 156 无头 DSP 端到端 38 / 38、桌面 Chrome 156 整页自动化实测 29 / 29（真实 build/web 产物 + 假麦克风设备，覆盖自动开始监听、getUserMedia 约束、AudioWorkletNode 注册、电平上报与输出 = 输入 × 输出音量、添加内置单块、手势提示与点击「开始监听」恢复）。尚未验证：真实吉他 + 真实声卡的人工听感、Edge 浏览器、页面隐藏 / 暂停后停止监听的整页行为。2026-11-03 已完成真机环回延迟实测三轮（数字见上一段），并据此把 AudioContext 默认改为 `latencyHint: 0`、上报浏览器采集缓冲与采集链路、改造延迟诊断面板、新增低延迟启动脚本 `tool/web_low_latency.sh`（`--audio-buffer-size=128`），并接入 `MediaStreamTrackProcessor` 低延迟采集（worklet 新增端口输入通道，离线回归 8 / 8）。

## 手柄线性扳机表情踏板（Linux / Windows / 电脑端浏览器，2026-11-02；2026-11-03 修复 Linux 断连循环）

Linux / Windows 桌面版与电脑端浏览器可以把游戏手柄的线性扳机当作哇音表情踏板，像踩表情踏板一样连续扫频。功能默认关闭，在“实时效果器”页效果器板下方的“手柄线性扳机 → 哇音踏板”卡片启用；选择左扳机或右扳机、目标哇音实例，可反向并校准量程。扳机读数以 25 毫秒节流写入哇音“位置”参数（对应 350–2200 Hz）。只在目标哇音处于手动模式、正在监听且已读到扳机读数时写入；自动扫频、未监听、效果链中没有哇音或未选择目标时不会改写位置，并在卡片内说明原因。关闭开关或离开页面会释放输入。

**切换到修复版本后请热重启或重启 App**：hot reload 不会替换已运行的 isolate 代码。

三个平台的读取方式不同：

- **Linux 桌面版**直接读取 `/dev/input/event*`：从 `/proc/bus/input/devices` 查找带线性扳机轴的手柄，支持热插拔重连，并尝试读取驱动实际量程（常见 0–255 或 0–1023）。多数桌面发行版会为已登录用户自动授权；若提示没有权限，可把当前用户加入 `input` 组（`sudo usermod -aG input $USER`，重新登录），或为手柄安装 udev 规则：新建 `/etc/udev/rules.d/99-gamepad.rules`，写入 `KERNEL=="event*", SUBSYSTEM=="input", MODE="0660", TAG+="uaccess"`，再执行 `sudo udevadm control --reload-rules && sudo udevadm trigger`。Flatpak / Snap 沙箱可能屏蔽 `/dev/input`。**如果 `event*` 因为权限打不开，会自动退回旧版 joystick 接口**（`/dev/input/js*`，默认 `0664`，任何用户都能读，不需要 `input` 组）：内核会把轴值缩放到 -32767..32767（0 为中点），这里按比例换算回 0–255 再驱动哇音；能用 evdev 时仍优先用 evdev，因为只有它知道驱动真实量程。 Linux 读取层在独立 isolate 里用非阻塞 `open` + `poll` 轮询：`poll` 被信号打断（`EINTR`）时按剩余时间重试，`read` 只有读到 EOF 才当作断开，`EAGAIN` 或空读继续轮询。
- **Windows 桌面版**通过 XInput 读取左/右扳机（0–255），仅识别 XInput 兼容手柄（Xbox 系列）；PlayStation 手柄需先经 Steam Input 或 DS4Windows 映射。
- **电脑端浏览器**通过浏览器 Gamepad API 读取标准映射里的第 6（L2）/ 第 7（R2）号按钮的模拟量（浏览器归一化到 0–1，这里换算成 0–255）。浏览器通常要先按一次手柄上的任意按键，才会把设备交给网页；页面必须在前台，切到后台时浏览器会暂停读取。找不到手柄时卡片会直接给出这三步排查提示：按一次手柄按键 → 保持网页在前台 → 在 Linux 上让浏览器能读 `/dev/input/event*`（`input` 组或 udev uaccess 规则；Chrome 官方规则缺失时浏览器同样看不到手柄）。没有标准映射的手柄（扳机是数字按键）会明确点名提示。

**先确认读取权限，但本次故障不是权限问题（2026-11-03 实测）**：`event*` 节点默认是 `0660 root:input`，用户不在 `input` 组时通常读不到；但 systemd 的 70-uaccess 规则会给 seat0 登录用户打上 uaccess 标签，xpad 这类手柄的 `event*` 节点又带 `ID_INPUT_JOYSTICK`，所以多数桌面会话本来就有读权限。本机实测当前用户可通过 ACL 读取 `/dev/input/event20`（`getfacl /dev/input/event20` 可确认），设备在线、打开正常；此前把阻塞归因于权限的结论已作废。网页端同样由浏览器进程自己读 `/dev/input`（Chrome 未装官方 `60-chrome-devices.rules` 时枚举不到手柄；Firefox 的 snap 版默认已连接 joystick 接口）。如果 `getfacl` 里确实没有当前用户，再按下面方式授权：uaccess 规则不用重新登录，加入 `input` 组需要重新登录。Flatpak / Snap 沙箱也可能屏蔽 `/dev/input`：

```bash
echo 'KERNEL=="event*", SUBSYSTEM=="input", MODE="0660", GROUP="input", TAG+="uaccess"' | sudo tee /etc/udev/rules.d/99-gamepad.rules
sudo udevadm control --reload-rules && sudo udevadm trigger
```

这一条命令同时修好桌面版与浏览器（浏览器能读到手柄，网页端就能用）；也可以把用户加入 `input` 组（`sudo usermod -aG input $USER`），但需要重新登录才生效。无线休眠、蓝牙断开或虚拟机 USB 直通断开会移除设备节点（本机 2026-11-03 实测手柄在线，不是本次故障原因）；系统里根本看不到设备时，卡片会说明扫描到多少个输入设备。仓库里带了一个诊断脚本，用来确认当前到底卡在哪一步：

```bash
build/flutter-sdk/bin/dart run tool/probe_gamepad.dart
```

它会列出系统中的输入设备、哪些带线性扳机轴、`/dev/input/event*` 与 `/dev/input/js*` 的权限、ACL 和能否打开，打印驱动上报的扳机轴量程，然后在这几秒里实时打印 ABS 事件和旧版 joystick 通道的轴读数（运行期间按一下右扳机就能看到数值变化），最后跑一次真实输入源打印快照。脚本要在宿主桌面会话里运行（沙箱或容器里看不到 `/dev/input`）；本次修复就是用它配合 `dart --profiler` 复现了每秒断连，并在修复后确认循环消失。

## 运行与使用

当前通过源码运行。安装 Flutter SDK，满足 `pubspec.yaml` 中的 Dart SDK 约束（目前为 `^3.12.0`），并准备目标平台开发环境。以下命令在项目根目录执行：

```bash
flutter doctor
flutter pub get
flutter devices
```

根据 `flutter doctor` 补齐目标平台所需环境，从 `flutter devices` 获取设备 ID。

| 平台 | 运行条件 | 启动命令 |
| --- | --- | --- |
| Android | Android SDK，已连接的设备或已启动的模拟器 | `flutter run -d <Android设备ID>` |
| iOS | macOS、Xcode、模拟器或完成签名配置的真机 | `flutter run -d <iOS设备ID>` |
| Windows | Windows 主机及 Visual Studio 的 C++ 桌面开发环境 | `flutter run -d windows` |

| Linux | Linux 主机及 Flutter 所需桌面构建依赖 | `flutter run -d linux` |
| Web | Chrome 及 Flutter Web 开发环境 | `flutter run -d chrome` |

启动后点击“吉他调音器”，默认开启“自动识别琴弦”，点击“开始调音”并允许麦克风权限。拨响任意一根接近标准音高的空弦，稳定约 0.18 秒后自动选择对应琴弦；点击琴弦可切至手动模式，重新打开开关可恢复自动识别。在安静环境中一次拨响一根空弦，根据“偏低 / 偏高”缓慢调整弦钮；指针进入中央 ±5 音分准音区后，先显示“接近准音 · 请保持”，稳定约 0.6 秒后显示勾号和“已调准”；超过 ±7 音分会取消确认。丢音后保留读数最多 3 秒；超过约 0.45 秒显示“上次读数 · 请重新拨弦”，并取消调准确认，3 秒后清空。自动识别遇到短暂不确定音高时也保留上次读数，确认切弦后重置。已降低弱音检测门槛以接续余音，未开启采集降噪。标准调弦从六弦至一弦为 E2、A2、D3、G3、B3、E4，基准 A4 = 440 Hz。

点击“停止调音”、返回首页或应用进入后台会停止采集；回到前台需要手动重新开始。音频仅在本机内存中分析，不保存、不上传。拒绝权限后可在系统或浏览器设置中授权再重试；无读数时请检查选弦、环境噪声和麦克风。自动识别仅接受距离标准目标 ±180 音分内的音高，严重走音时请手动选弦；识别不进行八度折叠。谐波、同时拨弦和设备采样率差异可能影响结果，实际调音效果仍待设备验证。

Linux 可安装 `pulseaudio-utils` 和 `ffmpeg` 以提供上述命令。Web 使用安全来源；其他平台请检查系统麦克风隐私设置。当前仅支持标准调弦与固定基准音。

首页进入“鼓机”打开“即兴工作台”，鼓机、Looper 和效果器放在同一页，无需切换面板。宽屏上方并排显示 Looper 和鼓机，下方为效果器；窄屏纵向排列，可滚动访问。鼓机音量 0–100%（默认 100%）、Looper 回放音量 0–400%（默认 100%）、效果器输出音量 0–100%（默认 50%）分别控制各自声音。鼓机音量可在播放中实时调节，不重启节奏；停止或切换预设保留音量，离页重置。

Android / iOS / Linux / Windows 进入工作台后会静音检测效果器引擎和声卡输入/立体声输出，检测后释放设备；点击“开始监听”才出声。可重新检测，失败显示原因；macOS 显示效果器不支持，鼓机与 Looper 仍可使用；电脑端浏览器本轮提供内置效果器（本次变更实现，自动化整页实测通过），但不支持 VST3 与湿声 Looper，工作台的 Looper 仍录原始输入。检测通过表示当时能打开设备，不能判断吉他是否已连接或保证演奏延迟；监听中若连续 3 秒收不到任何数据（精确数字静音），会提示输入设备可能不是吉他所在接口，并给出「重新连接设备」「声卡与输入通道」两个动作。Android / iOS / Linux / Windows 的 Looper 共用效果器输入，录制效果链后的声音；需先开始监听，声卡采样率设为 48000 Hz，不会自动回退为干声。其他平台继续录原始输入。离开工作台释放全部会话。鼓机与 Looper 独立循环，目前不自动量化到小节、锁定速度或拉伸录音。

1. Android / iOS / Linux / Windows 先在下方效果器开始监听，实际采样率需为 48000 Hz，调整好音色（桌面可选择输入通道，移动端使用系统当前路由提供的单声道输入）；再点击“录制第一层”或按空格。其他平台首次允许麦克风权限后开始演奏。
2. 再踩一次结束首层并循环播放；首层至少 0.3 秒、最长 30 秒，达到上限自动结束。
3. 播放中再踩一次开始叠录，再踩结束；叠录满一圈也会自动结束。新层加载好后按当前循环位置加入，原有层持续播放；最多 6 层。
4. 按 S 停止／恢复（恢复从循环开头开始），Z 撤销最近一层，X 清空全部。停止会丢弃未完成的录音，保留完成层；进入后台停止且不自动恢复，离开页面清空。

没有踩钉时，可在 Looper 面板开启“智能录音”，点击“智能录制第一层”，先保持安静半秒测底噪，再开始弹琴。持续琴声触发录制，停奏约 2 秒后自动裁掉首尾空白并循环；短促首尾碰触尽量忽略，保留少量起音和尾音余量及段内短暂停顿。等待期间再点主按钮取消，录制期间可提前结束，停止按钮丢弃未完成录音。30 秒内未触发会停止并提示；起录后最长采集 30 秒，裁剪后不足 0.3 秒需重录。仅首层生效，后续叠录维持整圈长度；清空后可切换模式。

设置中可调“智能录音触发门槛”（默认 −45 dBFS）：轻弹不触发就调低，杂音误触发就调高；检测到较高底噪时会自动提高实际门槛。此功能按信号强弱判断边界，不能从人声、持续杂音或鼓机外放中单独分离吉他，也不做全段降噪；建议耳机或声卡直录。超过 2 秒的演奏停顿会被视为结束，不自动对齐鼓机拍点。弱尾音、首尾杂音过滤及循环听感仍待真实设备试听。六平台共用处理逻辑，权限与设备限制沿用下文；不新增音频文件保存。
